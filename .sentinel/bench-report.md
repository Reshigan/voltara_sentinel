# Pelo bench

- verdict: below bar (bar 8/10)

- **correctness**: 3/10 — public/index.html hardcodes a static SCHEMA object that doesn't match the actual API routes or data model (e.g., meter fields list "site_id" as integer but the spec requires UUID TEXT; no dashboard KPI endpoint is called; the UI never fetches /api/dashboard or /api/digest). Fix: replace the static SCHEMA with actual API calls and align field types with the spec.
- **design**: 4/10 — public/index.html defines CSS custom properties directly in a <style> block with no token layer (no design-tokens file, no shared source of truth for colors/spacing/type). Fix: extract all design tokens into a separate tokens.css file imported by index.html, and reference only those tokens in component styles.
- **accessibility**: 5/10 — public/index.html status pills use only color (green/amber/coral) with a dot but no text label or icon that conveys meaning without color. Fix: add a text label inside each pill (e.g., "Active", "Warning", "Critical") alongside the dot.
- **responsive**: 6/10 — public/index.html has a mobile breakpoint at 760px that collapses the sidebar, but the KPI grid uses auto-fit with minmax(180px, 1fr) which can cause horizontal overflow on very narrow screens (e.g., 320px). Fix: change minmax to min(180px, 100%) to prevent overflow.
- **states**: 3/10 — public/index.html shows loading skeletons and empty states, but there is no error state for individual CRUD operations (e.g., form submission failure only shows a toast, no inline error messages on fields). Fix: add per-field error messages linked via aria-describedby in the form.
- **security**: 4/10 — public/index.html passes a tenant parameter via query string but there is no server-side validation or sanitization of this value; it's directly interpolated into API URLs. Fix: validate tenant against a whitelist or sanitize to alphanumeric only on the server side.
- **robustness**: 4/10 — public/index.html's api() function catches errors but doesn't handle network failures gracefully (e.g., no retry, no timeout, no AbortController). Fix: add a fetch timeout and retry logic for transient failures.
- **maintainability**: 3/10 — public/index.html is a single 300+ line file mixing HTML, CSS, and JavaScript with no module boundaries, no separation of concerns, and a hardcoded SCHEMA that duplicates the data model. Fix: split into separate files (app.js, styles.css, schema.js) with clear responsibilities and import the schema from a shared source.
- **form**: 2/10 — public/index.html uses bare strings for field types ("text", "integer", "real") instead of a typed contract; there is no shared TypeScript interface or enum for the data model. Fix: define a shared types.ts with literal union types for all fields and import it into both client and server.
