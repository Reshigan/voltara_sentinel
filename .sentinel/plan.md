package.json — Project manifest with scripts for typecheck (tsc --noEmit), lint (eslint src/), test (bun test), and deploy (wrangler deploy). Dependencies: hono, uuid. DevDependencies: @cloudflare/workers-types, typescript, eslint, @typescript-eslint/parser, @typescript-eslint/eslint-plugin, wrangler.
tsconfig.json — TypeScript strict-mode configuration targeting ESNext with module resolution bundler, paths for src/*, types for @cloudflare/workers-types.
.eslintrc.json — ESLint configuration extending @typescript-eslint/recommended with rules: no-unused-vars error, no-console warn, semi error, quotes single, no-explicit-any warn.
wrangler.toml — Cloudflare Workers configuration: name voltara, main src/index.ts, compatibility_date 2024-01-01, d1_database binding DB pointing to voltara-db, assets directory public/, bindings for ASSETS.
migrations/0001_init.sql — Initial D1 schema: CREATE TABLE site, meter, reading, tariff, alert, audit_log with all columns, constraints, foreign keys, and indexes as specified in the data model. All tables include tenant TEXT NOT NULL DEFAULT 'default' column. Enable WAL mode, set busy_timeout pragma.
migrations/0002_seed.sql — Demo seed data: 3 sites, 5 meters across those sites, 2 tariffs, 20 readings spanning last 7 days, 3 alerts (1 open, 1 acknowledged, 1 closed), 5 audit_log entries. All with tenant='default'. Skipped in test harness.
src/types.ts — Frozen contract: entity interfaces (Site, Meter, Reading, Tariff, Alert, AuditLog) matching D1 schema exactly. API response types for every endpoint (list, get, create, update, delete per entity + dashboard KPIs + digest + import + health). Handler type aliases (e.g., SitesListHandler, MetersCreateHandler) using Handler<T> from lib/http. KPI response shape: { totalSites, activeMeters, dailyKwh, openAlerts }. SiteCard shape: { id, name, region, meterCount, totalKwh, alertCount, status }. Digest response shape: { totalKwh, peakDemandKw, newAlerts, acknowledgedAlerts, topSites: [{name, kwh}], criticalSites: [{name, alertCount}] }.
src/routes.ts — Route table: array of Route objects mapping HTTP method + path pattern to handler imports from handlers/*. Covers all CRUD endpoints, dashboard KPI, digest, CSV import, health. Paths: /api/sites, /api/sites/:id, /api/meters, /api/meters/:id, /api/readings, /api/readings/:id, /api/readings/import, /api/tariffs, /api/tariffs/:id, /api/alerts, /api/alerts/:id, /api/alerts/:id/acknowledge, /api/dashboard/kpis, /api/dashboard/sites, /api/digest, /api/health.
src/handlers/sites.ts — Site CRUD handlers: listSites (cursor pagination, tenant filter), getSite (by id + tenant), createSite (validate name/region/capacity, insert with UUID), updateSite (validate, update, audit log if capacity changes), deleteSite (cascade). All use prepared statements. Test: test/sites.test.ts.
src/handlers/meters.ts — Meter CRUD handlers: listMeters (cursor pagination, tenant filter, optional site_id filter), getMeter, createMeter (validate serial format 6-20 alphanumeric, kind enum, status enum, site exists, insert with UUID), updateMeter (validate, audit log on status change), deleteMeter. Anomaly detection runs synchronously on reading insert (in readings handler) but meter status changes trigger audit. Test: test/meters.test.ts.
src/handlers/readings.ts — Reading CRUD + CSV import: listReadings (cursor pagination, tenant filter, optional meter_id filter), getReading, createReading (validate kwh/demand_kw >= 0, taken_at ISO 8601, meter exists, insert with UUID, then run anomaly detection: query meter's 30-day avg and stddev, if new reading > 3 stddev from mean, insert WARNING alert within same D1 batch), deleteReading. CSV import handler: parse multipart/form-data, validate headers (meter_serial,taken_at,kwh,demand_kw), batch insert 500 rows per D1 batch, return {imported, errors[]}. Test: test/readings.test.ts.
src/handlers/tariffs.ts — Tariff CRUD handlers: listTariffs (cursor pagination, tenant filter), getTariff, createTariff (validate name unique, rate_per_kwh > 0, band enum), updateTariff, deleteTariff (sets meter tariff_id to NULL via FK). Test: test/tariffs.test.ts.
src/handlers/alerts.ts — Alert CRUD + acknowledge: listAlerts (cursor pagination, tenant filter, optional status/meter_id filters), getAlert, createAlert (validate severity enum, message non-empty, meter exists), updateAlert, acknowledgeAlert (set status=ACKNOWLEDGED, acknowledged_at=now, audit log entry). Test: test/alerts.test.ts.
src/handlers/dashboard.ts — Dashboard KPI and site cards: getDashboardKpis (single query: SELECT COUNT sites, COUNT active meters, SUM readings.kwh for today, COUNT open alerts — all tenant-filtered), getDashboardSites (query: for each site, subquery meter count, SUM readings.kwh, COUNT open alerts, derive status color from alert severity). Both return JSON matching KPI and SiteCard types. Test: test/dashboard.test.ts.
src/handlers/digest.ts — Daily digest handler: single query with subqueries for totalKwh (last 24h), peakDemandKw (MAX demand_kw last 24h), newAlerts (COUNT opened last 24h), acknowledgedAlerts (COUNT acknowledged last 24h), topSites (top 3 by kWh last 24h), criticalSites (sites with open CRITICAL alerts). Returns DigestResponse JSON. Test: test/digest.test.ts.
src/handlers/health.ts — Health check handler: returns { status: 'ok', db: 'connected', uptime: Date.now() - startTime }. No tenant filter, no auth. Test: test/health.test.ts.
src/lib/anomaly.ts — Anomaly detection utility: export async function checkAnomaly(db: D1Database, meterId: string, newKwh: number, tenant: string): Promise<void>. Queries last 30 days of readings for meter, calculates mean and stddev, if newKwh > mean + 3*stddev, inserts WARNING alert. Runs within same D1 batch as reading insert. Test: test/anomaly.test.ts.
src/lib/validation.ts — Input validation utilities: isValidUUID(str), isValidSerial(str) 6-20 alphanumeric, isValidISO8601(str), isValidEnum(value, allowed[]), isPositiveNumber(value), isNonNegativeNumber(value). Used by all handlers before DB operations. Test: test/validation.test.ts.
public/index.html — Single-page cockpit console: KPI band (4 metric cards in 2-col mobile, 4-col desktop), CSS Grid of site cards (1-col mobile, 2-col tablet, 4-col desktop). Each card: site name, region label, 3 inline stat pills (meters, kWh, alerts), status dot left-border. Click expands inline detail panel via CSS :target. Slide-over forms for create/edit. All interactions use <form> POSTs with hx-target for partial updates via HTMX. Empty states with centered message + CTA. Skeleton loading with pulse animation. Keyboard navigable, Escape closes panels. Fetches tenant from ?tenant= query param.
public/styles.css — Cockpit console styling: surface #0f172a, panel #1e293b, ink #f8fafc, muted #94a3b8, accent #22d3ee, alert #f59e0b. Type scale 12/14/16/20/28/40px on 4px grid. CSS Grid layouts for KPI band and site cards. Status pills with color + text. Slide-over panel animations. Skeleton pulse @keyframes. WCAG 2.1 AA contrast ratios. Focus visible styles. Print styles for digest report.
public/app.js — Client-side interactivity: HTMX configuration (default swap, target), form validation (serial format, required fields, numeric ranges), slide-over panel open/close with Escape key, focus management (trap focus in open panel, return on close), dashboard auto-refresh after mutations (HTMX triggers), tenant param forwarding on all fetch requests. No framework — vanilla JS with HTMX library loaded via CDN.
